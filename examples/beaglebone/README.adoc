// M5 · #45 · Demo Setup Guide — HTTP Adapter (Weg 1, kein Eingriff ins BBB-Repo)

== Überblick

Demonstriert wie ein *BeagleBone Black* (BME280-Sensor, GPIO) über den UDAL HTTP Adapter als reguläres UDAL-Device exponiert wird — ohne eine einzige Code-Änderung im link:https://github.com/paul-fleischmann-com/beaglebone_black[beaglebone_black-Repo].

[cols="1,3"]
|===
| Weg | HTTP Adapter (Polling) — Weg 1 aus #45
| UDAL-Version | v1.0.0
| BeagleBone IP | `192.168.7.2:5000` (USB-OTG Standard)
| Poll-Intervall | 5 s (konfigurierbar)
|===

.Architektur
....
BeagleBone Black      Bridge (Laptop)       UDAL Gateway         Client
:5000 REST API  <-->  :5001 /properties  <--  HTTP Adapter  <-->  gRPC :50051
BME280 · GPIO         beaglebone-bridge.py    pollt :5001          REST :8080
....

NOTE: Der UDAL HTTP Adapter erwartet Endpunkte nach der *UDAL HTTP Device Convention*
(`GET /properties`, `GET /properties/{path}` mit Wire-Format `{"float":…}`).
Da die BeagleBone-API ein eigenes REST-Schema hat (`/api/v1/bme280`), vermittelt
`beaglebone-bridge.py` zwischen beiden — einmalig auf dem Entwicklungsrechner,
kein Code auf dem BeagleBone selbst nötig.

=== GPIO-Einschränkung

NOTE: `SetProperty` für `http`-Transport-Devices ist in dieser UDAL-Version noch nicht
implementiert (HTTP Adapter, Issue #24 AC: nur Read-Pfad).
Die `gpio_usr0`-Property ist lesbar; zum Schreiben kann man direkt an die BeagleBone-API
schicken: `POST http://192.168.7.2:5000/api/v1/gpio/60` — oder Weg 2 (#47, Go SDK) abwarten.

== UDAL Gateway starten

WARNING: `--dev` deaktiviert TLS — nur für lokale Demo-Umgebungen.

.Binary
[source,bash]
----
./udal-gateway \
  --dev \
  --bootstrap-api-key demo-key-123 \
  --grpc-addr :50051 \
  --http-addr :8080 \
  --metrics-addr :9090
----

.Docker
[source,bash]
----
docker run --rm \
  -p 50051:50051 -p 8080:8080 -p 9090:9090 \
  -e UDAL_DEV_INSECURE=true \
  -e UDAL_BOOTSTRAP_API_KEY=demo-key-123 \
  ghcr.io/paul-fleischmann-com/udal:1.0.0
----

.Gateway-Health prüfen
[source,bash]
----
curl http://localhost:9090/health
# → {"status":"ready"}

== Bridge starten

Die Bridge übersetzt die BeagleBone-API in die UDAL HTTP Device Convention.
Sie läuft auf dem Entwicklungsrechner (oder einem Proxy-Host im selben Netz).

[source,bash]
----
# Python 3.9+ — keine externen Abhängigkeiten
python3 examples/beaglebone/beaglebone-bridge.py \
  --bbb-url http://192.168.7.2:5000 \
  --port 5001
----

.Bridge testen — UDAL Wire-Format prüfen
[source,bash]
----
# Bulk-Snapshot (vom Gateway gepollt)
curl http://localhost:5001/properties
# → {"temperature":{"float":23.45},"humidity":{"float":48.72},...}

# Einzelner Wert
curl http://localhost:5001/properties/temperature
# → {"float":23.45}
----

== Capability-Schema anlegen

Das Schema folgt dem UDAL Capability Schema Format v1.0 und wird beim Gateway registriert.

.beaglebone-bme280.schema.json
[source,json]
----
{
  "udal": "1.0",
  "kind": "DeviceCapability",
  "metadata": {
    "name":        "beaglebone-bme280",
    "version":     "1.0.0",
    "description": "BeagleBone Black — BME280 Sensor + GPIO USR0 LED",
    "tags":        ["sensor", "gpio", "beaglebone"]
  },
  "properties": {
    "temperature": { "type": "float", "unit": "°C",   "readOnly": true },
    "humidity":    { "type": "float", "unit": "%rH",  "readOnly": true },
    "pressure":    { "type": "float", "unit": "hPa",  "readOnly": true },
    "gpio_usr0":   { "type": "int",   "min": 0, "max": 1,
                     "description": "USR0 LED (GPIO 60) — 0=off, 1=on" }
  }
}
----

.Schema beim Gateway registrieren
[source,bash]
----
curl -X POST http://localhost:8080/api/v1/capabilities \
  -H "Authorization: Bearer demo-key-123" \
  -H "Content-Type: application/json" \
  -d @examples/beaglebone/beaglebone-bme280.schema.json
----

== Device registrieren

Der HTTP Adapter konfiguriert sich über Device-Labels.
`http.endpoint` ist die Basis-URL der Bridge (nicht die BBB-API direkt).

[source,bash]
----
curl -X POST http://localhost:8080/api/v1/devices \
  -H "Authorization: Bearer demo-key-123" \
  -H "Content-Type: application/json" \
  -d '{
    "name":       "beaglebone-01",
    "capability": "beaglebone-bme280@1.0.0",
    "transport":  "http",
    "labels": {
      "http.endpoint":      "http://localhost:5001",
      "http.poll_interval": "5s",
      "location":           "desk",
      "hw":                 "beaglebone-black"
    }
  }'
----

.Device-Liste prüfen
[source,bash]
----
curl http://localhost:8080/api/v1/devices \
  -H "Authorization: Bearer demo-key-123"
----

TIP: Mit `grpcurl` alternativ über gRPC: +
`grpcurl -plaintext -H "authorization: Bearer demo-key-123" -d '{"name":"beaglebone-01",...}' localhost:50051 udal.v1.DeviceService/RegisterDevice`

=== Python SDK

[source,bash]
----
pip install udal-sdk
----

[source,python]
----
import asyncio
from udal import UDALClient

async def main():
    async with UDALClient(
        "localhost:50051",
        api_key="demo-key-123",
        insecure=True
    ) as client:
        temp = await client.get_property("beaglebone-01", "temperature")
        print(f"Temperatur: {temp.value}°C")

asyncio.run(main())
----

client, _ := udal.Dial("localhost:50051",

    udal.WithInsecure(),
)
defer client.Close()

val, _ := client.GetProperty(ctx, "beaglebone-01", "temperature")
fmt.Printf("Temperatur: %.2f°C\n", val.Float())
----

== Live-Streaming (Subscribe)

Property-Updates in Echtzeit empfangen — Gateway pollt Bridge alle 5 s und pusht Änderungen.

[source,python]
----
async def stream():
    async with UDALClient("localhost:50051", api_key="demo-key-123", insecure=True) as c:
        async for update in c.subscribe("beaglebone-01", "temperature"):
            print(f"[{update.timestamp}] {update.value:.2f}°C")

asyncio.run(stream())
----

[source,bash]
----
grpcurl -plaintext \
  -H "authorization: Bearer demo-key-123" \
  -d '{"device_id":"beaglebone-01","property_path":"temperature"}' \
  localhost:50051 udal.v1.DeviceService/SubscribeProperty
----

== GPIO direkt schreiben (über Bridge)

Da `SetProperty` für den HTTP Adapter noch nicht implementiert ist (kein Write-Pfad in Issue #24),
GPIO-Schreiben direkt an die BeagleBone-API:

[source,bash]
----
# LED einschalten
curl -X POST http://192.168.7.2:5000/api/v1/gpio/60 \
  -H "Content-Type: application/json" \
  -d '{"value": 1}'

# LED ausschalten
curl -X POST http://192.168.7.2:5000/api/v1/gpio/60 \
  -H "Content-Type: application/json" \
  -d '{"value": 0}'
----

TIP: Write-Support via UDAL `SetProperty` kommt mit Weg 2 (Go SDK, Issue #47).
